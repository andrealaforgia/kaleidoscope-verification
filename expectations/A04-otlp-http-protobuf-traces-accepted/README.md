# A04 — otlp-http-protobuf-traces-accepted

## Surface

Aperture (OTLP ingest gateway). Operator/integrator-facing.

## Behaviour

Given aperture is running with both listeners bound (gRPC `:4317`, HTTP
`:4318`)
And a sink is configured (any of `stub` or `forwarding`; A04 is
agnostic to the choice — round-trip-to-downstream is E01's job)
When an OTLP/HTTP/protobuf client `POST`s a binary-encoded
`ExportTraceServiceRequest` with N spans to `:4318/v1/traces`,
Content-Type `application/x-protobuf`
Then aperture responds HTTP 200
And aperture's stderr emits one
`event=sink_accepted signal=traces span_count=N` line
naming the resource's `service.name` and `transport=http_protobuf`.

## Notes

`transport=http_protobuf` in the `event=request_received` line is the
distinguishing field versus A01 (`transport=grpc`). This is what the
expectation is verifying at the byte level: the HTTP/protobuf code
path is what handled the request.
